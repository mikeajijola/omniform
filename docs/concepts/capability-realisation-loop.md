# Capability-realisation loop

The user expresses intent through any interface. Lily is the default natural-language interface, but it does not own company truth or call providers.

```text
USER -> LILY -> COMPANY CAPABILITY -> REQUIREMENTS -> REALISATION
  -> agents / skills / connectors / workflows / schedules / people / machines
  -> PROVIDERS -> REAL WORLD -> EVIDENCE -> CAPABILITY STATE -> LILY
```

A company capability is an outcome-oriented organisational ability. A resource capability offering is a lower-level ability supplied by an agent, person, connector, workflow, system, partner, provider, or machine. A selected `CapabilityRealisation` composes offerings to cover requirements. Attachment alone is not proof of realisation.

Missing coverage is valid. It can remain missing, become partial, be blocked or deferred, or be accepted explicitly through governance. Requirements for human authority are stated precisely; the model never hides them as a vague dependency.

## Semantic and deterministic boundary

```text
SEMANTIC
intent, interpretation, candidate decomposition, explanation
  |
  v
STRUCTURED HANDOFF
validated capability intent and proposed plan
  |
  v
DETERMINISTIC
coverage, policy, authorization, apply, state, evidence, drift
  |
  v
SEMANTIC
evidence interpretation, explanation, validated learning
```

Schedules declare *when* an operation, workflow, observation, agent task, reconciliation, or plan refresh should run. Workflows declare *how* operations compose. Hosting-specific schedulers remain provider implementations.
